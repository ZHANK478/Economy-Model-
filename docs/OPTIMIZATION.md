# Оптимизация без изменения экономических уравнений

Базовая версия: опубликованная версия 73, коммит `5ce04954060a9ea597c769eb8089f1e2a1869604`, экономическая ревизия 22. Изменения относятся к выполнению кода; новая экономическая ревизия не вводилась.

## Что обнаружено и изменено

Профиль CPU показал значительные расходы на JSON-копирование рабочего состояния, синхронизацию долей семей и повторное построение списков предприятий. Это профиль сценарного запуска Node, а не измерение на телефоне.

1. При переходе месяца архивы расселения, предприятий, собственников, коррупционных операций, долговечных товаров, миграции и иностранного капитала больше не проходят глубокое копирование вместе с изменяемыми счетами. Каждый новый ход получает собственный массив истории; завершённые записи используются как неизменяемые данные. Та же схема уже применялась к основному журналу, потреблению, социальной защите и обороне. Никакие записи не удалены, окна хранения не сокращены.
2. При синхронизации долей список семей каждой группы строится один раз на вызов, а не для каждого предприятия. Веса распределения вычисляются один раз. Порядок суммирования и корректировки долей сохранён.
3. При расчёте распределения богатства балансовая стоимость предприятия вычисляется один раз на наблюдение, а не снова для каждой семьи и группы. Общая стоимость долей группы тоже вычисляется один раз. Постоянного кэша между ходами нет: изменения цен, долгов, собственности и капитала учитываются заново.
4. Для оценки банковских требований в социальных индикаторах список предприятий строится один раз на наблюдение.
5. Удалены неиспользуемые именованные импорты из 15 модулей. Это очистка зависимостей; основной выигрыш скорости дают предыдущие пункты.

Уравнения долгов, цен, потребления, инвестиций, политической реакции, коррупции и долговечных товаров не заменялись. Сходные формулы разных экономических объектов не объединялись автоматически: правила дивидендов, банковских требований и оценки капитала могут различаться по смыслу. Старые ветви ревизий оставлены для загрузки и воспроизведения исторических партий. Их возраст сам по себе не делает их ненужным кодом.

## Проверка сохранности

Полный набор тестов: **475 пройдено, 0 ошибок**. Дополнительный тест замораживает архивы предыдущего состояния и проводит 122 месяца, включая достижение предела 120 записей. Проверяется, что следующий ход использует независимые массивы и не переписывает прошлое.

Сравнение с отдельной неизменённой копией базового коммита: `scripts/verify-optimization.mjs`. У всех сценариев фиксирован `nameSeed`, общие внешние шоки и одинаковые решения. Сравниваются помесячные метрики, полные состояния на контрольных месяцах и в конце, полный экспорт JSON, загрузка, продолжение и воспроизведение. В сравнении состояний нет численного допуска: используется точное совпадение сериализованных данных. Метаданные исходников в таком запуске одинаковы (`unbuilt-source`); опубликованная сборка закономерно получает новый хеш исходников.

Сценарии охватывают три уровня дохода, сырьевую и диверсифицированную экономику; президентскую, парламентскую, персоналистскую, партийную, военную и смешанную системы; сохранение исторических уравнений ревизий 1, 9, 17, 20 и 21. Политическая партия прекращается при фактическом завершении полномочий или потере суверенитета.

Результат: **17 сценариев, 1 536 месячных переходов, 17 загрузок, 17 продолжений и 17 воспроизведений**. Все сравнения прошли.

Точные счётчики и хеши: [optimization-validation.json](optimization-validation.json).

## Скорость и ограничения

Результаты воспроизводимого отдельного замера: [optimization-benchmark.json](optimization-benchmark.json). Метод: два отдельных процесса на каждую версию, чередующийся порядок запусков; по 180 ходов для трёх стран. Политика и оборона выключены именно для этого измерения, чтобы все случаи прошли полный горизонт. Экспорт, импорт и контрольное хеширование не входят во время хода. Во время измерения другие проверки не запускались.



Среднее время расчёта 180 месяцев по двум запускам:

| Старт | До, с | После, с | Сокращение времени |
|---|---:|---:|---:|
| Бедная | 9.11 | 6.43 | 29.5% |
| Средняя | 9.54 | 6.23 | 34.6% |
| Богатая | 8.81 | 5.95 | 32.5% |

Размер полного сохранения намеренно не сокращён: оптимизация глубокого копирования не удаляет диагностические записи. Пиковая память и отзывчивость Android/Windows здесь не измерялись. Расчёт валютного равновесия, сериализация большой истории и сохранение могут по-прежнему занимать время. Перенос расчётов в Worker и изменение формата архива в эту правку не входят.

Браузерная проверка локальной сборки: обычный переход месяца и восстановление автосохранения после перезагрузки прошли; оформление сохранено. [Снимок проверки](optimization-ui.jpg).

Предыдущие исследовательские отчёты остаются историческими отчётами своих сборок. Точное A/B-сравнение подтверждает сохранение вычислений, а не эмпирическую истинность всех уравнений модели.

## Воспроизведение

```sh
git worktree add --detach /absolute/path/baseline 5ce04954060a9ea597c769eb8089f1e2a1869604
node --test --test-concurrency=3 tests/*.test.js
node scripts/verify-optimization.mjs /absolute/path/baseline
node scripts/benchmark-optimization.mjs /absolute/path/baseline
npm run build
```

Проверки и измерения следует выполнять последовательно, чтобы нагрузка тестов не искажала сравнение скорости.
